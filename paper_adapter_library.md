# The Engram Is an Address: Three Applications of One Theory for Test-Time Memory

Michael Bonsignore

---

An engram — a single vector computed by mean-pooling a transformer layer's hidden states — is not content. It is an address into the model's representation manifold. Whether that address resolves depends on whether the model has been trained on the territory it points to. The vector did not gain information; the model gained the ability to interpret it.

We validate this directly. Same engram, same model, same injection. Before test-time training: 0 out of 20 passkeys. After: 20 out of 20. From this single claim, three architectures fall out. One absorbs new knowledge with zero forgetting. One compresses the KV cache by 4×. One composes multiple adapters for multi-fact queries. Same vector, same theory, three deployment surfaces. All validated in 58 experimental phases on a single RTX 5070 Ti across four days.

## The decomposition

Test-time memory factors into three orthogonal subsystems. The **addressing system** — the engram as a pointer. The **knowledge system** — the weights at each address, base plus LoRA. The **execution system** — the standard transformer forward pass.

Prior work collapses these. Test-time training makes memory equal to parameters, causing forgetting. RAG makes memory equal to context, paying quadratic cost. Knowledge editing makes memory equal to surgical mutation, causing cascades. Our claim: memory should be a modular function over the residual stream, loaded on demand and unloaded when irrelevant.

The **centroid theory of context** bridges addressing and knowledge. Each attention head computes a convex combination of value vectors — a centroid in a learned space. This is a first-order approximation, not a theorem. But it predicts: attention does not need to reconstruct the sequence; it needs to land in the same attention basin. The engram lands in the same K-space basin as the passage, and that suffices.

Three regimes confirm the theory. Out-of-distribution with no training: 0/20, the address points off-manifold. In-distribution prose with no training: 18 percent of context information, a broad neighborhood. After training: 20/20, a sharp basin. The engram's information density is not a property of the vector — it is a property of the knowledge system at the address the vector points to.

## The K-space measurement and the L0/L5 duality

Fifty WikiText passages, 128 tokens each. We extract two engrams per passage — the layer-5 mean and the layer-0 mean (input token embeddings before any block has run) — inject each as a single hidden-state position, and measure how the K and V vectors it produces at every layer compare to the passage's mean K and V.

**Each engram is well-aligned at the layer it was extracted from.** The L5 engram has K cosine **0.82–0.89** at layers 1–5 (random baseline ≈ 0) but a bootstrap failure at layer 0 — L5 vectors are not what `W_k_layer0` was trained against. The L0 engram is the dual: cosine **0.988** at layer 0 (no bootstrap problem; L0 vectors are exactly what the layer-0 projection expects) decaying to 0.65 by layer 5. Each is structurally indistinguishable from the passage K centroid in its own layer's K-space, but neither is at every layer.

K consistently aligns better than V (0.82–0.89 vs 0.65–0.70 for L5). K determines which positions attention selects; V determines what flows back when a position is selected. The routing channel is near-perfect; the value channel is approximate. This asymmetry is the empirical signature of the addressing-vs-knowledge channel split that the decomposition predicts, and it is what makes routing fundamentally different from content reconstruction. The duality between L0 and L5 sets up the central architectural choice in the rest of the paper: which engram to use, where, and why.

## Application 1: per-passage adapter library

A frozen 510M-parameter base model. LoRA adapters on blocks 4 and 5, rank 128, 2.6 million parameters each. A single-stage cosine-threshold router: 99 percent recall, 98 percent specificity at threshold 0.50. An earlier identity-autoencoder gate (Phase 39) was measured against a mixed query stream and found to be worse than a coin flip at 48 percent specificity — combining it with the cosine threshold *reduced* recall by 21 points. We dropped it.

**Headline result.** Same-prompt retrieval: 20/20, drift +0.000 percent. Training-distribution paraphrases: 60/60. Held-out paraphrases: **58/60 retrieved at 60/60 routed — 100 percent routing correctness, 97 percent retrieval** — using a learned linear projection L0 → L5 trained once at library construction. The 2 of 60 missing retrievals are both correct-routing-with-decoding-failure cases (the right adapter loaded, the model fails to produce the passkey through greedy decoding). At 100 percent routing the architecture is at the model's intrinsic generation ceiling on this benchmark.

**The architectural principle: L5 for training, L0 for inference.** The LoRA adapter is shaped at training time by gradient signal that lands at L5 — the LoRA lives at layers 4–5 and the next-token loss propagates through it there. The routing key at inference is L0 — the input embedding is the most stable representation across paraphrases because it has not yet been mixed by attention into divergent patterns for different surface forms. The bridge between them is a 1024×1024 linear projection W trained once at library construction with L5 as the supervision signal: W learns the directions in L5 space that distinguish *this library's adapters* and applies them to L0 queries at inference. One embedding lookup plus one matmul. No forward pass at routing time. The projection encodes what L5 knows about the library; L0 carries the query; the cosine over their projected comparison routes.

**The path to 97 percent runs through three measurements.** **Phase 44** swept four single-layer engram extractors against held-out paraphrases and found L0_mean wins by 15 points over L5_nonstop_mean (90 vs 75 percent). Stopword filtering *hurts* at L0 because template tokens are stable lexical vectors at the embedding layer — they add stabilizing signal across paraphrases instead of the noise they added at L5. **Phase 45** tested whether mixing L0 and L5 directly via average cosine would dominate either alone, and found it does not — the mix lifts numeric routing (11/15 → 15/15) but breaks entity (15→9) and fact (14→10), ending at 80 percent. The cancellation pattern was the clue: L5 carries useful signal exactly where L0 is weakest, but mixing them *uniformly* throws away signal in both directions. The fix is to mix them *selectively per direction in feature space*. **Phase 47** trains a 1024×1024 projection W with InfoNCE such that L0_p @ W matches L5_p (positive pair, same prompt) and is far from L5_q (negative pair, different adapter). The projection learns the L5-discriminative directions for the library and rotates L0 onto them. Numeric routing recovers to 15/15 — the binding constraint of the entire arc — while entity, technical, and fact stay at 14–15/15.

**Leakage check.** This is structurally different from the engram-as-cheat-sheet leak in earlier (V16) experiments where prepended engrams became visible to all subsequent positions through causal attention during teacher-forced evaluation. Phase 47's routing is a cosine comparison between two precomputed CPU vectors, not a forward pass — there is no attention during routing, no token sequence, no path by which the engram could carry the answer. The L5 keys and L0 queries are computed under the base model with `reset_lora_to_zero(model)` called before extraction; the matched adapter is loaded only *after* the routing decision is recorded. Phase 47b inspected all 60 held-out generations and confirmed every reported retrieval is a genuine answer in answer-relevant context (zero substring false positives), with the post-answer pattern of *verbatim quoting from the absorbed passage* showing the LoRA holds the full passage at token granularity, not just a passkey lookup. The remaining honest concern is that the projection W is library-specific and would need fine-tuning when new adapters are added — a deployment-flow concern, not a leakage one.

**Saliency-weighted absorption.** Phase 52 used a learned attention-pooling encoder (Phase 51) to identify which token positions carry the most information in a passage. Weighting the next-token prediction loss by these saliency scores during LoRA training concentrates gradient on the informative tokens. Result: **rank-64 saliency-weighted adapters achieve 20/20 retrieval**, matching rank-128 uniform-loss adapters. Same retrieval also holds at **75 steps** instead of 150. Saliency weighting enables **2× rank compression and 2× faster convergence** with no quality cost. The saliency scores are computed once per passage before absorption begins and are not updated during training.

**The user never waits.** First query on novel content served from context normally. Background worker trains a clone of the LoRA in 1397 milliseconds for 100 percent verbatim retrieval. A second background pass adds paraphrase keys in another 1392 milliseconds for 100 percent paraphrase retrieval. Lock-free atomic upgrade. The user-visible latency on first query is base-model latency.

**Storage frontier.** The rank sweep pinned the floor at 128 — matching rank 512 on every test. Rank 256 scored 19/20, *worse* than rank 128, confirming interference rather than capacity. Training time is constant across ranks (~3 seconds per passage). Int8 quantization stacks for another 4× with zero quality delta. Combined: **16× compression** vs the original rank-512 fp32 prototype. Sparse magnitude pruning at threshold 5e-3 adds 1.8× more for 29× total at the cost of held-out retrieval. A 1000-passage library at the conservative 16× point fits in 2.6 gigabytes. With saliency-weighted rank-64 absorption, the storage halves again to **32× compression** at rank-64 + int8.

**Adapter clustering is architecturally impossible.** Phase 53 tested whether passages with high L0 cosine similarity (0.96–0.97) could share a single adapter. For all five closest pairs in the benchmark, continuing training on passage B fully erased passage A — 0/5 survived in either training order. Even same-template, same-type passages differing only in passkey value cannot be co-absorbed at rank 128. The one-adapter-per-passage architecture is necessary, not merely convenient.

## Application 2: engram-compressed KV cache

The same engram extraction substitutes for tokens in the cache. Six conditions on 50 WikiText passages, 200-token context plus 56-token continuation. Full context: perplexity 17.71. Engram replacing the distant half with recent tokens kept: 18.41 — closing **92 percent** of the full→none NLL gap, essentially free at 2× compression. Replacing 75 percent: 22.25, **84 percent** of the gap closed at 4× compression. The curve is smooth from 0 to 384× with no knee. Each doubling costs roughly 0.5 perplexity points.

**The recency asymmetry is the finding.** Compressing the *distant* half closes 92 percent of the gap. Compressing the *recent* half closes only 32 percent. Two engrams give nothing over one — the bottleneck is per-engram bandwidth, not segmentation. The 18 percent engram-only floor is identical across our experiments at this model size.

**Attention pooling lifts the floor.** Phase 51 replaced mean pooling with a learned attention-pooling encoder — a single learned query vector that attends over the hidden states and produces the vector that minimizes continuation NLL when injected as sole context. Information recovery rises from **18 percent to 28 percent**, a 10-point improvement from choosing a better single vector. Phase 55 extended to multiple learned queries: K=5 tokens recover **30 percent** at 40× compression, the empirical ceiling for small-token-count engrams. K=10 does not improve over K=5 — the additional queries overfit rather than capturing new information.

**The 30 percent ceiling is a feature, not a bug.** Phase 50 measured V-space singular value spectra across all layers. The effective rank is ~48 — no single direction captures the signal. SVD engrams (the mathematically optimal single vector by variance) recover **negative** information (-12.5 percent), worse than no context. The maximum-variance direction is dominated by magnitude patterns, not semantic content. Mean pooling works better than SVD because it captures the centroid, which is semantically grounded.

Three pre-training experiments attacked the ceiling from different angles. **Phase 56** added a V-space reconstruction loss — a direct decoder at each layer forcing W_V to preserve input information. V-space alignment improved from 0.71 to 0.73, but WikiText perplexity degraded from 21 to 43, and information recovery *dropped* from 18 to 14 percent. The extra information in V amplified across layers and destabilized training, forcing the model to make V-space lossy again. **Phase 57** added sigmoid-gated residual connections on top of the reconstruction loss to prevent that amplification. The gates held V-space alignment at **0.805** — a 10-point improvement over baseline — by constraining the residual stream to convex combinations. But the constrained signal flow capped learning capacity: perplexity converged at 46 instead of 21, and information recovery fell to 7 percent. You can have well-organized V-space or good language modeling, but the unconstrained residual stream that makes the model powerful is what makes V-space lossy. **Phase 58** tested whether richer feature interactions help, replacing the attention score with a full bilinear form (q^T W k, with learned d_head × d_head matrices per head). At convergence (43K steps), the bilinear model matched the standard model on perplexity (44 vs 44) and gained 3 points on information recovery (15.7 vs 12.6 percent). The model used the off-diagonal capacity extensively — bilinear weights moved far from identity (||W-I|| ≈ 2.9) and stayed full rank (effective rank 128, σ₁ at 1.6 percent). Cross-dimensional feature interactions are real and useful, but the 3-point gain doesn't break the ceiling.

**V-space is intentionally lossy.** All three interventions confirm the same finding from different angles: the reconstruction loss shows that forcing V to preserve information hurts prediction quality; the gated residuals show that constraining amplification preserves V-space alignment at the cost of model capacity; the bilinear form shows that richer feature interactions produce a modest gain but don't change the fundamental compression. Downstream layers need abstracted, compressed representations, not faithful copies of the input. The 70 percent that V discards is not lost information — it is intentional compression that downstream computation requires. The 30 percent ceiling is an architectural property of how transformers use V-space, not a training failure.

**The L0/L5 question, applied here.** Phase 33b measured continuation perplexity under L0-engram injection (instead of the L5-engram baseline). The result is a clean partial-win: at the standard operating point (engram_then_tokens, 2× compression with recent tokens kept) L0 and L5 are tied within noise (91 vs 92 percent gap closed). At extreme single-vector compression (engram_only) L0 underperforms by roughly half (8 vs 18 percent) because the engram is the *only* source of K/V at every layer and the model needs the late-layer alignment that L5 provides. We use L0_mean as the unified default for the standard operating point and reserve L5 only for the extreme-compression edge case. Phase 45's heterogeneous two-position prefix was tested as a unification candidate and found to add nothing useful — at the standard operating point the pair ties L0 and L5 alone (92 percent), and at engram_only it gets 20 vs L5's 18 percent for 2× the position cost.

Measured on natural-language WikiText prose only. Not tested on code, math reasoning chains, or structured data, where token-level dependencies may break the recency-dominance pattern that makes compression cheap.

## Application 3: compositional retrieval

Phase 29 found that weight-merging two adapters scores 0/5 BOTH on compositional queries where each scores 100 percent alone. We initially reported this as a failure of LoRA composition. We were wrong about the operator.

Weight merging computes `x · ((A1+A2)/2) · ((B1+B2)/2)`, which expands to four terms including two cross terms — `x·A1·B2` and `x·A2·B1` — that project the input through one adapter's input basis and back through the other's output basis. The cross terms are pure interference. They produced "The code code for the northern facility is the S.S.A. code code..."

**The correct linearization is activation-level block-stacking.** Concatenate the rank dimensions: `A_stacked = [A1 | A2]`, `B_stacked = [B1 ; B2]`. Block matrix multiplication gives `x·A1·B1 + x·A2·B2` exactly, with no cross terms. Five lines of matrix manipulation, implemented as a single rank-2R LoRA load. Oracle pair selection with block-stacking: **4/5 BOTH** (was 0/5 with weight merging).

**Clause-split routing.** A compositional query is a *set* of constraints. The joint engram is dominated by whichever clause has more content tokens — joint-engram top-2 routing returns the right pair only 5/10 of the time. The fix is to split the query on connectives ("Also", "and"), route each clause to its own top-1 adapter, then block-stack the routed adapters. Phase 42: **4/5 BOTH with 10/10 routing correctness**, exactly matching the oracle. The composition negative result fully bridges.

This is structurally a content-addressable mixture-of-experts pattern. Experts are per-passage adapters. The router is the engram. Expert combination is rank-stacked LoRA. Adding a new expert is O(1) — no router retraining required because routing is unsupervised cosine matching.

**The K=2 ceiling.** Phase 43 swept K ∈ {1, 2, 4, 8} on oracle pair selection. K=1 retrieves 20/20. K=2 retrieves 4/5 ALL. **K=4 collapses to 0/5 ALL** (35 percent mean fraction recovered — typically 1–2 of 4 passkeys per trial). K=8 saturates at 5 percent. Block-stacking generalizes mathematically to any K, but the model handles K=2 only at this rank and scale. The fact-type adapter wins 4/5 trials at K=4 while the numeric type wins 0 — adapter dominance under residual-stream competition rather than uniform degradation.

**Phase 46 ruled out the obvious fix.** What if we train the LoRA adapters to occupy more L5-orthogonal subspaces during absorption, expecting them to interfere less when block-stacked? Phase 46 added an L5-contrastive auxiliary loss to absorption. The contrastive loss did exactly what it was designed to do — reducing mean off-diagonal anchor cosine from 0.296 to 0.200 — but K-capacity *regressed*: K=2 dropped from 90 to 70 percent mean fraction; K=4 from 35 to 15. **The K=2 ceiling is a property of the LoRA matrices as linear operators on the residual stream, not of the L5 hidden states they happen to produce on a specific input.** Pushing two specific L5 outputs apart on a specific input doesn't make the underlying matrix products `A1·B1` and `A2·B2` more linearly independent in the operator space that activation-level summation lives in. The K=2 ceiling won't yield to representation-level orthogonalization. Operator-level fixes — per-adapter scale reduction at K=4 (untested under √K scaling), sequential generation, or smaller per-adapter rank so K=4 occupies the same residual-stream budget as K=2 at rank 128 — are the remaining untested directions.

Half-scale per adapter fails at K=2 (each adapter needs its full training magnitude). Sparse pruning at the aggressive 29× compression point cuts composition from 4/5 to 2/5. The deployment tradeoff: 16× compression preserves composition, 29× degrades it.

## The path through failure

Full-model TTT: +473 percent drift after 20 absorbed passages. Shared-LoRA continual rehearsal: 50–75 percent cumulative retrieval, chaotic. Doubling rank from 512 to 1024 dropped cumulative retrieval from 50 to 20 percent — interference, not capacity. Passage-derived keys: 60 percent routing — wrong distribution. Prompt-derived keys: 100 percent — the library indexes query manifolds, not content. Single-key per adapter: 50 percent on paraphrases, style dominates identity. Multi-key plus multi-paraphrase training: 100 percent, both necessary.

Six pooling strategies tested at L5. Norm-based hurts. Softmax collapses at 3 percent. Stopword filtering jumps from 63 to 77 percent — Phase 31's right move at the wrong layer. Phase 44's L0_mean (no forward pass, no filter) gets 90 percent. Phase 47's L0→L5 projection (one matmul, trained once) gets 100 percent routing and 97 percent retrieval — bounded now by generation accuracy, not by routing.

The composition story is the cleanest example of how the framing matters. We said "LoRA composition is hard" when we should have said "weight merging is the wrong linearization." Only by being able to write a 250-line script and run it in five minutes did we discover that the right linearization was five lines of matrix manipulation away.

**Seven attempts to improve V-space directly — all negative or marginal, all diagnostic.** Phase 48: KL-divergence regularization against the frozen base model during LoRA absorption. Trades retrieval for drift reduction at a ratio the architecture doesn't need (per-adapter loading already gives +0.000 percent reset drift). Phase 49: metadata-enriched token embeddings (POS, entity type, saliency, query type) bolt-on to a pre-trained model. Full-context NLL explodes from 2.87 to 8.87 — the model never saw enriched embeddings during pre-training. Phase 49b: pre-training from scratch with metadata on 90 percent of batches. The model learns to use metadata (4.4 percent PPL improvement when present) but the metadata-free path degrades, and V-space quality is unchanged. Phase 54: saliency-weighted continued training of the base model. PPL drifts +22 percent in 2K steps — the concentrated gradient distorts rather than reorganizes V-space. Phase 56: auxiliary V-space reconstruction loss during pre-training. V-space alignment improves (0.71→0.73) but PPL degrades from 21 to 43 and information recovery drops from 18 to 14 percent. Phase 57: reconstruction loss with gated residuals to prevent signal amplification. V-space alignment holds at 0.805 (+10 points) but the constrained residual stream caps perplexity at 46 and information recovery falls to 7 percent — the model trades language modeling capacity for V-space organization. Phase 58: bilinear attention (q^T W k with full d² feature interactions). The model uses the off-diagonal interactions extensively (W far from identity, full rank) and gains 3 points on information recovery, but does not break the 30 percent ceiling. Each negative result closed a direction and constrained the design space. Together they establish that V-space lossiness is load-bearing: the model needs the compression that V provides, the unconstrained residual stream that makes the model powerful is what makes V-space lossy, and richer feature interactions produce modest gains but cannot change the fundamental architecture.

## Limitations

The architecture delivers indexed recall of learned manifolds, not flexible memory. Adapters don't abstract across content. The system memorizes specific passages but does not synthesize topic-level understanding from their composition.

The K=2 ceiling on Application 3 is the binding constraint and is operator-level, not representation-level. Phase 46 ruled out the simple fix. Per-adapter scale reduction at √K, sequential generation, and smaller per-adapter rank are untested. Natural-language clause decomposition beyond explicit "Also/and" connectives is also open.

Application 2's results are measured on WikiText prose only. Code, math reasoning chains, and structured data are untested and the recency-dominance pattern that makes compression cheap may not transfer.

The cosine router cannot distinguish novel in-distribution content from novel off-manifold content for KV compression — a deployed system needs a manifold detector we have not built.

Prepend-as-token engram injection is a lower bound. Direct K/V cache injection bypassing the layer-0 bootstrap would likely shift the compression curve upward and is the most likely source of additional headroom on Application 2.

Engram aliasing at scale is unmeasured. Routing is clean at 20 passages. At 1000 we have no reason to expect collapse but have not measured. At 100,000 the angular separation between absorbed-prompt engrams may shrink and the cosine threshold may become lossy, motivating hierarchical indexing.

The Phase 47 projection W is library-specific. Adding new adapters at deployment time requires extending the projection's training set or fine-tuning W. We have not measured how the cost of doing this scales with library size.

Twenty passages with template paraphrases. Small and synthetic.

## The virtual memory analogy

Base model as kernel. Adapters as memory pages. The cosine router (with the L0→L5 projection) as the page table. Cosine-below-threshold as a page fault that either falls back to the kernel or triggers a new absorption. With Application 3, multi-page address translation works too — two pages can be loaded simultaneously and their contents combine through activation-level summation. The analogy predicts what comes next: paging policies, working-set caches, hierarchical address spaces, page compression, shared library pages.

## What we believe

The sharper version of "the engram is an address" is this: **transformers don't need the original data — they need a point that reactivates the same computation.** Memory is re-entering a trajectory through representation space, not storing state. Compression works when the trajectory is stable enough that one vector suffices to re-enter it. Training is what makes a trajectory easier to re-enter — what carves the basin around it. The three applications are three uses of the same operation: KV compression is approximate trajectory replay, per-passage adapters patch missing trajectories, compositional retrieval sums trajectories whose interference structure is benign at K=2.

**V-space is intentionally lossy, and that lossiness is load-bearing.** Seven independent experiments (Phases 48, 49/49b, 54, 56, 57, 58) attempted to improve V-space information preservation through regularization, metadata enrichment, saliency-weighted training, reconstruction objectives, constrained residual propagation, and bilinear feature interactions. Every approach that succeeded in reorganizing V-space (Phase 57: V-cos 0.71→0.81; Phase 56: V-cos 0.71→0.73) degraded language modeling quality by a factor of two or more. The one approach that preserved language modeling quality (Phase 58: bilinear attention, PPL matched) gained only 3 points on information recovery. Phase 57 is the sharpest demonstration of the tradeoff: gated residuals held V-space alignment 10 points above baseline throughout training by constraining the residual stream to convex combinations — but the constrained signal flow that preserved V-space organization was the same constraint that capped the model's learning capacity. The unconstrained residual stream is what makes transformers powerful, and it is what makes V-space lossy. You cannot have both. The 30 percent information recovery ceiling (Phase 55) is not a training failure. It is the cost of the compression that makes next-token prediction work. The K/V asymmetry (K at 0.82–0.89, V at 0.65–0.70) is not a deficiency in V — it reflects the fundamentally different jobs of the addressing channel (which needs fidelity) and the content channel (which needs abstraction).

The architectural principle that ties everything together is **L5 for training, L0 for inference**. The LoRA adapter is shaped at training time by gradient signal that lands at L5. The routing key at inference is L0, computed by a single embedding lookup. The bridge — when you want L5's discriminative power without L5's forward pass — is a small linear projection trained once at library construction with L5 as supervision. Phase 47 implements the bridge and gets the architecture to its routing ceiling. Phase 46 ruled out the naive version of this principle (an L5-contrastive loss on the LoRA itself) by showing it conflates two distinct jobs: making addresses discriminative (which the projection does) versus making operators non-interfering (which is the K=2 problem and lives in matrix space, not representation space).

**The practical improvements work within the 30 percent ceiling, not against it.** Attention pooling (Phase 51) reads V-space better: 18→28 percent recovery. Multi-token engrams (Phase 55) read more of it: 28→30 percent at K=5. Saliency-weighted absorption (Phase 52) writes adapters more efficiently: 2× rank compression, 2× faster convergence. None of these required V-space to change. They succeed precisely because they accept V-space as it is — intentionally lossy, architecturally constrained — and optimize around that constraint rather than trying to remove it.

The context window has been doing two jobs at once: passing data to the model, and reactivating the model's existing computation. The engram does the second job alone. For content the model has had time to absorb, the context window can do strictly less. For novel content the context window still does what it always did — first-pass queries, the routing engram itself, and clause decomposition for compositional queries all still need it. We are not claiming the context window is obsolete. We are claiming that it handles less as the model learns more.

The decomposition is simple enough to be wrong about in interesting ways — and that is what makes it worth reporting. The composition story is the example. Phase 29's negative result was correct as far as it went, but the framing was wrong. We said "LoRA composition is hard" when we should have said "weight merging is the wrong linearization." The right linearization was five lines of matrix manipulation away. We found it by being able to write a script and run it in minutes.

The engram is an address. Training is what makes it resolvable. 58 phases. Four days. One GPU.

The model that learns is the model that wins.
